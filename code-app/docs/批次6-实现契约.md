## 1. 完成标志（逐条可验）

1. 工作台待办「**通过**」→ 处方 `APPROVED`、`reviewer_id`/`review_time` 非空、**新增 1 条 `dispense_record`（状态 `PENDING`）**、实例 `APPROVED`、任务 `DONE/APPROVE`。
2. 工作台待办「**驳回**」→ 处方 `REJECTED`、`reject_reason` = 意见、实例 `REJECTED`、无新增调剂记录。
3. **两条路径同结果**：同一处方用「药房审核屏（`POST /api/prescription/<id>/review`）」或「工作台（`POST /api/workbench/todo/<id>/approve`）」审批，落库结果**逐字段一致**（这是本批第一号设计目标：消除双实现）。
4. **越权被拒**：无 `prescription:review` 的账号调工作台审批 → 中文拒绝，且状态不变。
5. 审批弹窗**只有「通过/驳回」**（无「退回」按钮）；构造 `return` 请求得到中文拒绝或明确不暴露。
6. **作废终止**：作废在办处方 → 处方 `VOIDED`、实例 **`TERMINATED`**（不是 `APPROVED`/`REJECTED`）、该实例 **0 个残留 `TODO` 任务**、`flow_history` 有 `TERMINATE` 记录。
7. 作废**已发药**处方 → 被拒（R-04 `BLOCK`），状态不变。
8. **转办**：把待办转给他人后，原办理人待办不再出现该任务、新办理人待办出现；**催办**：写一条 `URGE` 历史，任务仍在。
9. **AI 区可拖拽调宽**：拖动改变宽度并持久化（刷新后保持）、双击复位；中间工作区不被压到不可用。
10. **用户菜单**：右上角下拉含「修改密码 / 配置大模型（仅管理员可见）/ 退出登录」；改密成功后**旧密码失效、新密码可登录**。
11. 顶栏标题为「**中医问诊系统**」（不再是底座文案）；访问 `/` 时工作区有 tab。
12. 工作台三页筛选生效（筛选后的列表与 `total` 自洽），业务单可跳转到对应屏幕并**按单号定位**。
13. **不回归**：批次 1/2/3/4/5 全量回归通过；模型门禁 + 双副本一致；演示库只读体检通过。

## 3. 块①：审批闭环（单一实现路径）

### 3.1 设计（**不要新写一套回写函数**）

事实：`prescription_service.review_prescription()`（批次 2 已交付）**已完整实现** §6.4：APPROVE → 写 `APPROVED`+`reviewer_id`+`review_time` + `Dispense_CreatePending` 建单 + `engine.approve`；REJECT → 写 `REJECTED`+`reject_reason` + `engine.reject`。
缺口在**工作台路径**：`workbench_service.approve/reject` 只调引擎、不碰业务。

**实现要求**：工作台审批由任务反查业务对象（`flow_instance.business_object_refs` → `aggregateId`/`businessId`），**调用同一个 `prescription_service.review_prescription(business_id, {"action": ..., "comment": ...}, user)`**，不得复制其逻辑、不得在 workbench 侧另写状态更新。
- 反查规则：`business_object_refs` 里 `aggregateId == 'AGG-PRESCRIPTION-001'` 的项取其 `businessId`；找不到 → 中文错误「未找到关联的业务单据」。
- 事务：工作台侧不另开事务（`review_prescription` 自身 `db.transaction` 内完成；引擎调用已在同一 conn）。若必须双写，务必同一 conn，禁止嵌套 `db.transaction`（详见 §4.3 说明）。
- 终态豁免：处方已是 `DISPENSING/ISSUED/VOIDED` 时，`review_prescription` 现会以「仅待审核可审核」拒绝——**保持该行为**（这是正确的防线），工作台侧把中文原因透传给用户。

### 3.2 越权

工作台审批**必须校验 M5 权限码**（不得只靠"登录 + 任务归属"）：任务 → `behavior_ref`（`Prescription_Review`）→ 权限码 `prescription:review`（由 `seed.permission_code` 派生，禁手写）。无权限 → 中文「无权限执行该操作」且状态不变。

## 4. 块②：作废终止分支 + 转办/催办

### 4.1 作废终止（M6 Q03 分支）

**现状（实测）**：作废在办处方 → 处方 `VOIDED`、待办无残留，但实例状态变成 **`APPROVED`**（`prescription_service.py:706` 用 `engine.reject(...)` 冒充终止）→ 实例终态语义错误。
**要求**：作废在办处方时，同一事务内把实例置 **`TERMINATED`**（`flow_service.terminate_instance` 的既有语义），取消全部 `TODO` 任务，写 `flow_history(action='TERMINATE')`；**不得**再以 `reject` 表达终止。
- 触发条件：`prescription.prescriptionStatus` 原为 `PENDING_REVIEW`（即审批在办）时执行；不在办则不动流程。
- R-04 三分派（`VOID_ONLY`/`VOID_WITH_ROLLBACK`/`BLOCK`）逻辑**保持不变**；仅替换"结束实例"的方式。
- **不做平台权限校验**：内部调用不校验 `flow:instance:terminate`（那是流程管理页面的平台权限）；权限由发起方的 `prescription:cancel` 把关。

### 4.2 转办 / 催办（**必须走工作台新接口，不能直接用 `/api/flow/*`**）

**实测事实（决定实现方式）**：`api/flow.py` 的 `PUT /tasks/<id>/transfer|urge` 挂了平台权限码 `flow:task:transfer` / `flow:task:urge`，而库里 `sys_permission` **只有 `flow:manage`**（平台权限），这两个码**不存在** → `require_permission` 判失败 → **只有 admin（超管旁路）能调用**；中药师在待办页点转办会 403。

**要求**：新增**工作台侧**接口并按其自身口径鉴权（与 approve/reject 一致）：
- `POST /api/workbench/todo/<int:task_id>/transfer`：入参 `assigneeId`（候选来自 `GET /api/users/options`，取启用用户）；校验调用者是该任务办理人或其角色/管理员（复用 `_load_task_and_check`）；内部复用 `flow_service.transfer_task`；写 `flow_history`（含原办理人 → 新办理人）。
- `POST /api/workbench/todo/<int:task_id>/urge`：同上鉴权；内部复用 `flow_service.urge_task`（写 `URGE` 历史）。
- 两者成功后返回中文提示；前端在待办行内提供入口（催办仅对 `TODO`）。
- `PUT /api/flow/tasks/<id>/transfer|urge`（平台侧）**保留不动**，登记为 §9 缺口。

### 4.3 事务边界（**实现期硬约束**）

`db.transaction(fn)` 每次**新开连接**；`flow_service.terminate_instance` 内部用 `db.execute(...)`（无 conn 参数）→ 若被 `prescription_service` 的事务内调用，会**在另一个连接上写库**（SQLite 锁竞争 / 提交边界错乱）。
**要求**：把终止逻辑做成**接受 conn** 的形式（如 `flow_service.terminate_instance(instance_id, user, conn=None)`，`conn` 传入时不再自开），`cancel_prescription` 传自己的 conn。

## 9. 已知缺口与不变项（登记，不在本批做）

1. **撤回**：模型 D-25 明确不支持；改方走「作废后重开」。若业务确需撤回，先改 M6 与需求文档，再另开批次。
2. `/api/workbench/todo/<id>/return`（底座能力）保留但前端不暴露（D-25：退回等同驳回）。

4. 工作台三页暂不做导出；不做工作台自定义布局。
5. 配置大模型页只读；如需在线改配置，另开批次（涉及凭据落盘方案）。
6. **平台权限码与种子不一致（既有缺陷，本批不改）**：`api/flow.py` 声明 `flow:definition:add/edit/publish`、`flow:instance:terminate`、`flow:task:transfer/urge`，而 `sys_permission` 只有 `flow:manage` → 这些写接口实际**仅 admin 可用**，非 admin 打开流程管理页会 403。本批通过"工作台侧新接口"绕开（§4.2），平台侧不一致登记待决。
7. `flow_instance.status` 新增取值 `TERMINATED`（由 `flow_service.terminate_instance` 既有实现写入）：工作台「我的申请」与流程列表的状态徽标需覆盖该取值，报表侧不涉及（已核：报表来源不含流程实例状态）。
