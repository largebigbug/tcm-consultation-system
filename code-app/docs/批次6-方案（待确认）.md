## 2. 拟做范围（4 块，可否决单块）

### 块 ① 审批闭环：状态回写 + 自动节点执行业务行为（**核心，建议必做**）
- 新增 `FlowEngine.sync_status_from_instance(instance_id)`：按实例状态与当前待办节点回写业务对象。
- **映射表（按现有枚举，不新增字典值）**：实例 `APPROVED` → 处方 `APPROVED 审核通过`；`REJECTED` → `REJECTED 已驳回`；`RUNNING` → `PENDING_REVIEW 待审核`（「待谁处理」由当前任务节点表达，不硬写进业务状态）。
- **不回写终态**：处方处于 `DISPENSING 已调剂`/`ISSUED 已发药`/`VOIDED 已作废` 时，流程回写**跳过**（防数据倒流）。
- 审批三动作（approve/reject/return）在**同一事务**内调用该回写；通过时同步写 `reviewer_id`/`review_time`。
- 自动节点（`SYSTEM_TASK`，如 Q05 创建待调剂记录）真正调用其 `behaviorRef`（`Dispense_CreatePending`）建单，而不是只写历史。
- **完成标志**：审批通过后处方状态为 `APPROVED` 且 `review_time` 非空；驳回后为 `REJECTED`；已发药处方被驳回时状态**不被改写**；Q05 执行后 `dispense_record` 实际新增 1 行。

### 块 ② 撤回 / 接转办催办（**建议做**）
- `FlowEngine.withdraw(instance_id, user_id, reason)`：仅**发起人**、仅 `RUNNING` 可撤；实例置 `CANCELED`（新增实例状态取值，需同步确认报表/列表口径），写 `flow_history(UNDO)`；处方回 `DRAFT 草稿` 并记撤回原因。
- 接口：`POST /api/workbench/requested/<instance_id>/withdraw`（发起人权限）。
- 工作台待办页接上已有的 **转办**（选目标用户）/ **催办**（写 `URGE` 历史）两个动作。
- **完成标志**：撤回后实例 CANCELED + 处方回草稿；非发起人撤回被拒（中文）；撤回已结束实例被拒；转办后任务办理人变更且原办理人待办消失。

### 块 ③ 三栏形态补齐（**建议做**）
- 右侧 AI 区**拖拽调宽**（拖拽条 + 宽度持久化到 localStorage，双击复位）。
- 右上角**用户菜单**下拉：修改密码（真实改密接口 + 校验）、**配置大模型（仅管理员）**、退出登录。
- 顶栏标题改为「中医问诊系统」；首页 `/` 也进 tab。
- **完成标志**：拖动改变 AI 区宽度且刷新后保持；用户菜单三项按角色显隐（非管理员看不到「配置大模型」）；改密成功后旧密码失效、新密码可登录；顶栏文案正确。

### 块 ④ 工作台三页筛选与业务单跳转（**建议做**）
- 待办/已办：按流程名称、时间区间、处理结果筛选；「查看业务单据」跳转到对应业务屏（处方 → 药房审核屏并定位该单）。
- 我的申请：显示当前节点、状态徽标；可撤回（块 ②）。
- **完成标志**：筛选后列表与计数一致；跳转目标屏能按单号定位；状态徽标与实例状态一致。
