- 响应体一律 `utils/response.ok/fail`（`{success, message, data, errorCode, traceId}`）；**业务失败 HTTP 200 + `success:false`**，参数/权限类用 400/401/403。

## 3. 后端接口

### 3.1 `GET /api/ai/status`（登录即可）

```json
{"success": true, "data": {"enabled": false, "provider": "deepseek", "model": "deepseek-chat",
 "configured": false, "hint": "AI 对话未启用：请在 backend/.env 配置 DEEPSEEK_API_KEY（或把 ai.provider 设为 mock 以离线演示）"}}
```

`configured` 判据：`provider=mock` → true；`provider=deepseek` → `api_key`（config.yaml 或环境变量 `DEEPSEEK_API_KEY`）非空。

### 3.2 `POST /api/ai/chat`（登录即可，`text/event-stream`）

请求体：

```json
{"message": "本月门诊量多少", "history": [{"role": "user|assistant", "content": "..."}],
 "context": {"screenId": "frmVisitStats"}}
```

- `history` 由前端内存持有（≤ 10 轮，超出由前端截断），**不落库**；后端只用于拼 prompt。
- 响应头：`Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。
- 未启用（口径 7）→ **503** + `fail(...)` JSON（不进入 SSE）。

### 3.3 SSE 事件（分片格式 `event: <type>\ndata: <json>\n\n`）

| 顺序 | 事件 | data 字段 |
|---|---|---|
| 1 | `message_start` | `{"messageId": str, "ts": "YYYY-MM-DD HH:MM:SS"}` |
| 2 | `delta`（可多次） | `{"text": str}` |
| 3 | `tool_call` | `{"toolCallId": str, "name": str, "arguments": {...}}` |
| 4 | `tool_result` | `{"toolCallId": str, "ok": bool, "summary": str, "rowsCount": int?, "error": str?}` |
| 5 | `render_payload` | `{"renderType": "text\|table\|chart\|action", "payload": {...}}` |
| 6 | `message_end` | `{"finishReason": "stop\|error", "toolCallCount": int}` |
| 7 | `error`（异常时，替代 5/6） | `{"message": 中文, "code": str}` |

`tool_call`/`tool_result` 成对出现，可多组；每个 `tool_result` 后必须紧跟对应 `render_payload` 或继续 `delta`。

### 3.4 渲染协议

| renderType | payload 字段 | 前端行为 |
|---|---|---|
| `text` | `{"text": str}` | 分段换行渲染（不引入 markdown 依赖） |
| `table` | `{"columns":[{"name","label"}], "rows":[{...}], "total": int, "truncated": bool}` | 复用全局表格 CSS 渲染 |
| `chart` | `{"chartType":"bar\|line\|pie", "xField": str, "yField": str, "rows":[...], "title": str?}` | `echarts-for-react` 渲染 |
| `action` | `{"type":"navigate", "screenId": str, "behaviorId": str, "label": str, "prefill": {...}?, "permissionCode": str}` | 渲染按钮 → 前端路由跳转；**不发起写请求** |

## 4. 工具清单与权限过滤

- 工具 schema **逐条**来自 `code-app/docs/批次5-工具清单（注册表抽取）.md`：
  导航 19（`nav_<screenId>`）/ 查询 7（`query_<BehaviorId>`）/ 报表 7（`report_<reportCode>`）/ 行为-只读 24（`action_<BehaviorId>`）/ 图表 1（`chart`）/ SQL 只读 1（`sql_readonly`）。
- **权限过滤**：按登录用户 `has_permission(user_id, code)` 过滤——未授权工具**不进入** system prompt 的工具清单与 function-calling schema；若模型仍请求 → `tool_result.ok=false`、`error="无权限执行该操作"`、`summary` 中文说明，并写审计。
- **只读边界（强制）**：`action_*` 工具**只返回** §3.4 的 `action` payload（跳转 + 预填），**禁止**调用任何业务写接口（`POST/PUT/PATCH/DELETE`）。
- `query_*` / `report_*` 复用既有服务：`services.report_service.list_report(code, params)`（M7 引擎，已支持条件组开关）与既有查询服务；参数取值域以模型为准，非法值按既有 400 中文口径。
- `mock` provider 必须能**驱动完整链路**（含至少一次 `tool_call`/`tool_result`/`render_payload`），供离线验收断言事件序列。

## 5. provider 抽象与配置

- 接口（`ai/providers/base.py`）：`chat(messages, tools) -> Iterator[Chunk]`，`Chunk` 为 `delta` 文本或 `tool_call`（name + arguments）。
- `provider=deepseek`：`POST {base_url}/chat/completions`，`stream: true`，`tools` 用 function-calling schema；`base_url` 默认 `https://api.deepseek.com`；`model` 默认 `deepseek-chat`；`api_key` 优先取环境变量 `DEEPSEEK_API_KEY`，其次 `config.yaml` 的 `ai.api_key`；**禁止硬编码密钥**。
- `provider=mock`：确定性离线实现（不联网），按 §4 驱动完整链路（验收脚本用它断言全部 SSE 事件）。
- `base_url` 为**空字符串时按默认值处理**（当前 `config.yaml` 的 `base_url` 为空）；`enabled:false` 与「未配置凭据」走同一降级口径。
- **环境变量覆盖（验收可测性，强制）**：优先级 `env > config.yaml`——`AI_PROVIDER` 覆盖 `ai.provider`、`AI_API_KEY` 覆盖 `ai.api_key`、`AI_BASE_URL` 覆盖 `ai.base_url`、`AI_MODEL` 覆盖 `ai.model`。验收脚本据此在**不修改 config.yaml** 的前提下切 `mock`；`GET /api/ai/status` 必须反映**覆盖后**实际生效的 provider/model/base_url（只回显 api_key 是否存在，绝不回显密钥）。
- `config.yaml` 的 `ai` 段（本批只放开取值）：

```yaml
ai:
  enabled: true          # 总开关（false 时同「未启用」口径）
  provider: deepseek     # deepseek | mock
  api_key: ""            # 留空则读环境变量 DEEPSEEK_API_KEY
  base_url: "https://api.deepseek.com"
  model: "deepseek-chat"
  max_tokens: 2048
  timeout_seconds: 30
  sql_limits: {default_limit: 100, max_limit: 500, timeout_seconds: 3}
```

## 7. 只读 SQL 工具安全边界（强制，逐条落实 + 验收）

| # | 规则 |
|---|---|
| 1 | 仅允许 `SELECT`（首关键字校验，忽略前导空白/大写） |
| 2 | 仅允许白名单表（`registry["db_whitelist"]` 的 13 张物理表） |
| 3 | 仅允许白名单字段（同表 `attributes`，共 139 个；未列出字段一律拒绝） |
| 4 | 强制追加 `LIMIT`（缺省 `default_limit=100`；超 `max_limit=500` 截断为 500） |
| 5 | 执行超时（`timeout_seconds=3`，用 `sqlite3` progress handler 中断） |
| 6 | 禁多语句（去尾分号后出现 `;` 即拒）、禁注释（`--`、`/* */`） |
| 7 | 每次调用写 `audit_logs`（成功与被拒都写） |

**只读入口（实测固化，验收按此调用）**：`sql_readonly.guard.execute_readonly(sql, default_limit=100, max_limit=500, timeout_seconds=3, db_path=None, progress_steps=1000)`；被拒时抛 `SqlRejected`（含中文原因），超时抛 `SqlTimeout`；成功返回 `(SqlVerdict, {"columns": [...], "rows": [...], "rowCount": n, "limit": n, "truncated": bool, "elapsedMs": n})`。**语义**：默认 `limit=100`；显式 `LIMIT` 被尊重但**上限 500**（`limit` 字段回显实际生效值，行数不超过库内实有行数）；`truncated=True` 表示因 limit 被截断。
**白名单口径**：以 M1 **属性名**（驼峰，如 `herbCode`）或其物理列名为准；**5 个默认字段（`flag` 等）不在白名单**，故 `WHERE flag = 1` 一律被拒（逻辑删除由业务层保证）。

**额外拒绝**：`INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/REPLACE/PRAGMA/ATTACH/DETACH/VACUUM/REINDEX/ANALYZE`、`sqlite_master` / `sqlite_%`、子查询引用非白名单表、`UNION` 拼接外部表、`SELECT *`（必须显式列出白名单字段）。
