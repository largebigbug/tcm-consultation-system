## 2. 模型与引擎侧（已完成，实现方只读参考）

### 2.1 模型 v2.1 关键变化

- **新增约定 13**：非 BASE 条件组必须**显式声明** `switchParameterRef`（组内一致），该参数必须存在于本报表 `parameters` 且 `required=false`；开关语义两种——
  - **① 显式 `switchActivateValue`**（如 `onlyAlert` 的 `true`）→「相等即参与」，未传时取参数 `defaultValue`；
  - **② 无 `switchActivateValue`**（Enum 开关，如 `triggerType`）→ `BOTH` 整组参与，其它取值仅 `triggerKind` 匹配的成员参与。
- `ALERT_FILTER` 组（条件 C08）补：`switchParameterRef: onlyAlert` + `switchActivateValue: true`。
- `TRIGGER` 组（C03/C04）补：`switchParameterRef: triggerType`。
- **修复的实质缺陷**：v2.1 之前 `ALERT_FILTER` 的开关只写在注释里 → 引擎无法定位 → 静默按「整组恒参与」→ 该报表**忽略 `onlyAlert`、恒只返回预警项**。

### 2.2 引擎行为（已实测）

| 调用 | 结果 |
|---|---|
| 不传 `onlyAlert`（默认 false） | 10 行 = 全部饮片（其中 1 行 `alertStatus=预警`） |
| `onlyAlert=true` | 1 行 = 仅预警项 |
| `onlyAlert=false` | 10 行 |
| `onlyAlert=abc` | HTTP 400「参数「仅看预警项」取值非法（可选 true / false）：abc」 |

> 布尔取值白名单：`true/1/yes/y` 与 `false/0/no/n`（大小写不敏感）；空串＝未传。**实现不得自行放宽或静默兜底。**

## 3. 屏改造规格（`frmHerbStock` 饮片库存与预警（含盘点））

### 3.1 数据源（唯一取数口径）

| 用途 | 接口 | 说明 |
|---|---|---|
| 列表查询 | `GET /api/report/QR-HERB-STOCK-001?<参数>&page=&size=` | 列/列序/合计**只认**返回的 `columns`/`summary` |
| 导出 | `GET /api/report/QR-HERB-STOCK-001/export?format=xlsx\|csv&<参数>` | 复用 `downloadReport`（`api/report.ts`）；导出与查询用**同一组**参数 |
| 盘点 | `POST /api/herb/<id>/stocktake` | **保留**（非报表能力），成功后刷新列表 |
| 对账（R-06） | `GET /api/herb/<id>/reconcile` | **保留**，展示账面/实盘差异 |

> 批次 1 的 `/api/herb/stock`、`/api/herb/stock/export` **保留但本屏不再调用**（避免破坏批次 1 自测；清理留给后续批次）。改造后本屏不得再出现这两个路径。

### 3.2 控件 → 参数映射（按 MU 控件 id 原样保留控件）

| MU 控件 id | 类型 | 映射到 M7 参数 | 备注 |
|---|---|---|---|
| `txtQryHerbName` | TEXTBOX | `herbName`（模糊） | — |
| `cboQryHerbCategory` | COMBO | `herbCategory` | 字典 `HERB_CATEGORY` |
| `cboQryToxicityLevel` | COMBO | `toxicityLevel` | 字典 `TOXICITY_LEVEL` |
| `cboQryAlertStatus` | COMBO | **`onlyAlert`** | 选「仅预警项」→ `onlyAlert=true`；选「全部/空」→ 不传（**模型无 alertStatus 参数**，此为 MU↔M7 缺口，见 §5） |
| `chkOnlyAlert` | CHECKBOX | **`onlyAlert`** | 与上一控件**同源**：任一为「仅预警」即 `true` |

| 工具栏 `btnQuery`/`btnReset`/`btnExport` | BUTTON | — | 见 §3.4 |

### 3.3 列与展示

- **列集合与列序一律取后端 `columns`**（15 列：`herbCode/herbName/aliasName/herbCategory/toxicityLevel/spec/origin/stockQuantity/lowStockThreshold/alertStatus/alertGap/minCommonDose/maxCommonDose/latestInboundDate/latestOutboundDate`），页面**禁止**手写 `<th>` 列表。
- 字典列（`herbCategory`/`toxicityLevel`）用 `valueLabels` 显示中文；`alertStatus` 后端已返回**中文**「预警 / 正常」，**直接展示，不得映射为 ALERT/NORMAL**；`alertGap` 为数值（`预警值 − 库存`）。
- 布局、控件 id、按钮文案保持 `批次4-屏幕规格（MU抽取）.md` 原样（与既有批次 1 实现一致处不变）。
- 保留盘点面板（`numStocktakeQty`/`cboFlowBizType`/**`dtpBizDate`**/`txtOperatorId`/`txaStocktakeRemark`/`btnStocktake`/`btnStocktakeCancel`）与「载入已有记录」交互。
- **修订（批次 4 实现期回修）**：原写 `dtpStocktakeDate`，MU 抽取文档实为 **`dtpBizDate`**，按「以 MU 抽取为准」修正；另登记两条实现期发现的权限事实——`GET /api/herb/<id>/reconcile` 需 **`herb:save`**（非本报表权限），`POST /api/herb/<id>/stocktake` 需 `herb:stocktake`（均已在 `api/herb.py` 核实），故「载入已有记录」按钮按 `herb:save` 控制可见性。

### 3.4 交互

- 查询：仅提交「已应用条件」（`applied`），回第 1 页；`Reset` 清空全部条件（`onlyAlert` 回默认 false）并回第 1 页。
- 分页：`size ∈ {20,50,100}`（后端上限 100，超出截断并在返回体回显实际 size）。
- 导出：按当前已应用条件 + 所选 `format` 下载；文件名由后端 `Content-Disposition` 给出。
- 权限：进入即校验 `herb:query-stock-and-alert`（无权限 → 中文提示、不发请求）；`btnStocktake` 需 `herb:stocktake`。
- 错误：接口 `message` 原样 `toast.error`（含布尔取值非法、无权限等中文提示）。
