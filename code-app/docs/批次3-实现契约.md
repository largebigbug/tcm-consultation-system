## 3. 报表引擎规范（子代理 A）

### 3.1 元数据来源

`ontology.registry.load_ontology()` 已把 M7 装载为 `registry["query_reports"]`（键＝报表 id，7 个）与 `registry["db_whitelist"]`（13 个物理表白名单，含 `table` 与 `attributes`）。**报表引擎必须完全由 M7 元数据驱动**：不得把列名/SQL 硬编码成 per-report 分支（唯一允许的例外见 3.6「跨行占比」）。

### 3.2 别名 → 物理表/列 翻译（关键，禁止臆造）

- `sourceObjects[].objectRef` 是 M1 聚合 id（如 `AGG-VISIT-001`）→ 物理表由 M1 聚合别名 snake_case 得到，**必须与 `registry["db_whitelist"]` 校验**，白名单外的别名一律抛中文异常（例：「报表配置引用了未知数据源 visitX」）。
- 列参照 `别名.属性名`（属性名为 M1 camelCase）→ 物理列 = 属性名 snake_case；**属性必须在白名单 `attributes` 内**，否则抛中文异常。
- 主键列固定 `id`（M7 v1.6 起 Join 全部为 `别名.外键 == 别名.id`）。
- `preAggregation` 别名（`itemAgg`/`visitPrescriptionAgg`/`flowAgg`）以 CTE 实现，CTE 内列名＝`preAggregation.columns[].name`，按 `groupBy` 键分组；本批用到：
  - `itemAgg`：`GROUP BY prescription_id` → `itemCount = COUNT(id)`、`doseTotal = SUM(single_dose)`；
  - `visitPrescriptionAgg`：`GROUP BY visit_id` → `prescriptionCount = COUNT(id)`、`doseSum = SUM(doses)`。
  - CTE 内同样必须 `flag = 1`。

### 3.3 表达式翻译规则

| 模型写法 | SQLite 落地 |
|---|---|
| `DATE_TRUNC(x, MONTH)` | `strftime('%Y-%m', x)` |
| `DATE_TRUNC(x, DAY)` | `date(x)` |
| `DATE_TRUNC(x, granularity)` | 粒度由查询参数 `granularity` 取值，**只允许 `DAY` / `MONTH`**（M7 约定 7），非法值抛中文异常 |
| `COUNT` / `COUNT_DISTINCT` / `SUM` / `AVG` / `MIN` / `MAX` | `COUNT(x)` / `COUNT(DISTINCT x)` / `SUM(x)` / `AVG(x)` / `MIN(x)` / `MAX(x)` |
| `SUM(CASE WHEN … THEN 1 ELSE 0 END)` | 原样保留（条件计数） |
| `x / y`（比率列） | 原样，外层加 `NULLIF(y, 0)` 保护除零（除零返回 NULL） |
| `format: 0.00%` | **不做百分比化**：返回 0~1 的小数（如 `0.6667`），由前端按 format 渲染为 `66.67%` |

- **`flag = 1` 过滤**：主表写在 `WHERE`；**LEFT JOIN 的表必须写在 `ON` 里**（写到 WHERE 会把 LEFT 退化成 INNER，是必须避免的经典错误）。
- **Enum 型参数的取值域一律以 M7 该参数 `defaultValue` 行注释为准（M7 约定 10）**，本契约不得自造或增补：`granularity`＝`DAY`/`MONTH`，`statsDimension`＝`HERB`/`FORMULA_TEMPLATE`，`triggerType`＝`OVERDOSE`/`TOXIC`/`BOTH`。字典/枚举外取值一律拒绝并给中文提示；**不得只认自造别名而拒绝模型取值**（例：不得只认 `FORMULA` 而使 `FORMULA_TEMPLATE` 报错）。
- **`SUBTOTAL(x)` → 窗口聚合 `SUM(x) OVER ()`**（M7 约定 7）：表示「跨全部分组的总计」，用于占比列（RPT-SYNDROME-DIST-001 `caseRatio`、RPT-HERB-USAGE-001 `formulaRefRatio`）。语义＝需求 5.3/5.4「分子与分母使用完全相同的筛选条件」；**分母必须与分子同条件**，且不受分页影响。
- **`fixedValue`（常量条件，M7 约定 6）**：条件无 `parameterRef` 而有 `fixedValue` → 恒参与，右值按下列规则翻译：
  - `fixedValue` 形如 `别名.属性名`（如 `herb.maxCommonDose`、`herb.lowStockThreshold`）→ **列引用**（`prescriptionItem.single_dose > herb.max_common_dose`）；
  - `fixedValue` 形如 `[A, B, C]` → **取值集合**，配合 `operator: IN` 展开为 `IN ('A','B','C')`（如 `[APPROVED, DISPENSING, ISSUED]`，对应需求 5.4「处方状态∈{审核通过,已调剂,已发药}」）；
  - 其余为**字面量**（如 `NONE`）→ 直接比较。
- **条件组的参与规则**（M7 约定 6）：`group: BASE` 恒参与（只受 `skipWhenParameterEmpty` 控制）；**非 BASE 的组为可选条件组**。本批只涉及 `TRIGGER` 组（QR-PRESCRIPTION-OVERDOSE-001 的「触发类型」）：
  - 参数 `triggerType = BOTH`（默认）→ TRIGGER 组全部成员按组内连接符参与（C03 **OR** C04）；
  - `triggerType = OVERDOSE` → 仅 `triggerKind = OVERDOSE` 的成员参与（C03）；
  - `triggerType = TOXIC` → 仅 `triggerKind = TOXIC` 的成员参与（C04）；
  - `triggerType` 取值非法 → 抛中文异常。
  - 组内按 `logicalConnector` 连接、组与 BASE 之间为 AND，整组加括号。
- **连接符与括号**：条件按 `group` 分组（同组 AND），组间用 `logicalConnector`；每组外层必须加括号，避免优先级错乱。
- **算子映射**：`EQ→=`、`NE→<>`、`GT→>`、`GE→>=`、`LT→<`、`LE→<=`、`LIKE→LIKE '%v%'`、`IN→IN (...)`、`BETWEEN→BETWEEN a AND b`。
- **空参数**：`skipWhenParameterEmpty: true` 且参数为空 → 该条件不参与；**否则缺参抛中文异常**（例：「缺少必填查询参数：挂号日期起」）。
- **日期默认值**：`MONTH_START`→当月首日、`MONTH_END`→当月末日、`TODAY`→当日（`YYYY-MM-DD`）。
- **字典参数**只接受 code（不接受 label），非法 code 抛中文异常。

### 3.4 接口与响应

```
GET /api/report/<reportCode>            # 分页查询
GET /api/report/<reportCode>/export     # 导出（?format=xlsx|csv）
```
- `reportCode` = M7 `query_reports[].id`（如 `RPT-VISIT-STATS-001`）。未知 code → `fail("报表不存在：xxx", status=404)` 或 400（二者择一，须自测覆盖）。
- 查询参数：M7 参数名（camelCase）+ 分页/排序覆盖参数 `page`、`size`、`sortField`、`sortDir`（`ASC|DESC`，仅当该列 `sortable: true`）。
- 响应 `data` 结构（**冻结**）：

```json
{
  "report": {"id": "RPT-VISIT-STATS-001", "name": "门诊量统计", "alias": "...",
             "objectType": "REPORT", "emptyValueDisplay": "-"},
  "columns": [{"name": "statDate", "label": "统计日期", "dataType": "Date",
               "format": "yyyy-MM-dd", "sortable": true, "visible": true}],
  "list": [{"statDate": "2026-09-30", "deptCode": "TCM_INTERNAL", "visitCount": 12}],
  "total": 123, "page": 1, "size": 20,
  "summary": {"visitCount": 88, "firstVisitCount": 40},
  "masterDetail": null
}
```
- `columns` 顺序＝M7 `resultColumns` 顺序，只返回 `visible: false` 之外的列？→ **全部返回**（含 `visible` 标记），前端按 `visible` 决定是否渲染（保持模型不被后端裁剪）。
- `summary`：仅当 M7 `reportOptions.totalFields` 非空时返回对象；**对 totalFields 逐列求和**（全量分组行之和，不受分页影响）；无数据时各键为 0；合计行不计算比率列（M7 totalFields 中不含比率列）。非合计报表 → `null`。
- `masterDetail`：仅 `QR-VISIT-PRESCRIPTION-001` 返回 `{"level":"VISIT","childKey":"prescriptions","childColumns":[…],"grandchildKey":"items","grandchildColumns":[…],"detailRowKey":"id"}`；其余报表为 `null`。
- 分页：`page` 自 1 起；`size` 默认取 M7 `pagination.defaultPageSize`(20)，上限 `maxPageSize`(100)，超上限**截断为 100 并返回实际生效 size**；`size<=0` 或非数字 → 400 中文提示。
- 排序：未显式传 `sortField` 时用 M7 `orderBy`（多列按序）；`sortField` 不在结果列或该列 `sortable=false` → 400 中文提示；排序字段一律走白名单，禁止拼接原始参数进 SQL。
- 全部 SQL 使用 `?` 参数化绑定（禁止字符串拼接参数值）。

### 3.5 导出

- `GET /api/report/<reportCode>/export?format=xlsx|csv`（其余参数同查询；`page/size` 忽略）。
- 权限与查询一致（**同一行为权限码**，需求 D-31 明确）。

- 文件名：`<报表名>_<YYYYMMDDHHmm>.<ext>`，中文用 `Content-Disposition: attachment; filename*=UTF-8''<urlencode>`。

## 4. 六张报表的取数口径与陷阱（A、B、C 共同遵守）

> 列/参数/条件/分组/排序/合计的**逐项定义以 `批次3-报表规格（M7抽取）.md` 为准**，本节只写口径与坑。

1. **RPT-VISIT-STATS-001 门诊量统计**：按 `DATE_TRUNC(visit.registerTime, granularity)` + 科室 + 医师 + 就诊类型分组。就诊人次=`COUNT(visit.id)`；就诊人数=`COUNT(DISTINCT visit.patient_id)`；初诊/复诊/已完成/已取消＝条件计数（字典 code `FIRST`/`FOLLOW_UP`、`COMPLETED`/`CANCELLED`）；复诊占比=`复诊人次/就诊人次`。**坑**：JOIN patient 只为取患者信息，不要因为 LEFT JOIN 产生行膨胀而让 `visitCount` 变大（`visit` 是主表且一行一就诊，膨胀只会来自 prescription 类一对多表——本报表不含）。
2. **RPT-SYNDROME-DIST-001 证型分布统计**：按 `syndromeId` 关联证型字典取 code/name；例数=`COUNT`；占比建议在 Python 侧按分组总数计算（避免依赖 SQLite 窗口函数），占比列 `format=0.00%` 返回小数。合计行只含 `caseCount`。
3. **RPT-HERB-USAGE-001 方剂与饮片使用统计**：**双维度** `statsDimension=HERB|FORMULA_TEMPLATE`（M7 注释取值，参数默认 `HERB`）。
   - **行单位＝处方明细**（M7 v1.8 已将主来源改为 `itemAgg`）：两个维度都不得为「无明细的处方」生成统计行；
   - `HERB`：按 `herb` 分组（饮片列有效），方剂列（`formulaCode/formulaName/formulaType/formulaRefCount/formulaRefRatio`）置 `null`；
   - `FORMULA_TEMPLATE`：按 `formula` 分组（方剂列有效），饮片列置 `null`；
   - 明细必须先按 `preAggregation` 预聚（**禁止「先去重再求和」**，M7 约定 5）；
   - 「使用剂数」取 `SUM(prescription.doses)`（口径待确认项①，按 M7 实现即为正确）；
   - 引用占比＝该方剂引用张数 / 全部引用张数。
4. **QR-VISIT-PRESCRIPTION-001 就诊与处方记录查询（主从）**：三层结构 —— 主＝就诊（行键 `id`，含 `visitPrescriptionAgg` 的 `prescriptionCount/doseSum` 聚合列）、从＝处方（`itemAgg` 的 `itemCount/doseTotal`）、明细分列用于导出扁平化。**分页作用于主行（就诊）**；`list[]` 每行附 `prescriptions: [...]`，每个处方附 `items: [...]`（若实现成本高，`items` 可为明细列数组，但键名固定）。作废相关字段（`prescriptionStatus`、`cancelReason`）必须在从表行上返回。
5. **QR-PRESCRIPTION-OVERDOSE-001 超量·毒性处方审核台账**：`triggerType` 默认 `BOTH` —— `OVERDOSE`＝`prescriptionItem.singleDose > herb.maxCommonDose`、`TOXIC`＝饮片毒性分级 `<> 'NONE'`（即 M1 字典 `TOXICITY_LEVEL` 的 `SLIGHT`/`TOXIC`/`HIGHLY_TOXIC` **三类全含**，**以 M7 C04 `sourceExpression` 为准**，机械抽取）；`exceedRatio = singleDose / NULLIF(maxCommonDose,0)`（保留 2 位小数）；INNER JOIN 明细与饮片（无明细的处方不出现在台账）。**坑**：「处理结果」与「处方状态」取值域重叠（阶段二遗留待确认项④），本批按 M7 列口径实现，不做额外解释。
6. **RPT-FOLLOWUP-COMPLETION-001 随访完成与失访分析**：按 `DATE_TRUNC(followUp.plannedFollowUpDate, MONTH)` + 科室 + 医师分组；计划随访数＝`COUNT`；已完成/已失访/各疗效等级＝条件计数（code `COMPLETED`/`LOST`、`CURED/MARKED_EFFECT/EFFECTIVE/INEFFECTIVE/AGGRAVATED`）；完成率＝已完成/计划、失访率＝已失访/计划、有效率＝（痊愈+显效+有效）/**已完成数**（M7 `sourceExpression` 分母为 `SUM(CASE WHEN followUp.recordStatus='COMPLETED')`，**不是计划数**；分母 0 → NULL）。**坑**：合计行的比率列不在 `totalFields` 中（模型定义），合计行不填比率，前端留空。
