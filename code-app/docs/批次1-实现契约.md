## 2. 全局强制约定（来自《指导书》）

1. **5 个默认字段**：每张业务表必须有 `created_by / created_at / updated_by / updated_at / flag`（`flag TINYINT DEFAULT 1`）。
   - 不显示在界面；由 service 自动写入 `created_by/updated_by = 当前用户 id`；`updated_at` 更新时显式 `CURRENT_TIMESTAMP`。
   - **逻辑删除**：删除一律 `flag=0`，不做物理删除；列表查询一律 `WHERE flag=1`。
2. **编号自动生成**（§3.1，本项目按需求文档口径微调，见下表），界面只读、不可编辑：

| 对象 | 字段 | 规则 | 示例 |
|---|---|---|---|
| Patient 患者 | `patient_no` | `PA` + 6 位流水 | `PA000001` |
| SyndromeType 证型 | `syndrome_code` | `Z` + 3 位流水 | `Z001` |
| FormulaTemplate 方剂 | `formula_code` | `F` + 3 位流水 | `F001` |
| Herb 饮片 | `herb_code` | `Y` + 4 位流水 | `Y0001` |
| HerbStockFlow 流水 | `flow_no` | `HF` + 6 位流水 | `HF000001` |

   > 统一用 `utils/codegen.py::generate_code(prefix, table, column, conn, digits)`，**必须在业务事务内调用**（避免并发重号）。
3. **主从表单单事务**（§3.5）：主表 insert 拿到 `master_id` 后，逐行写从表并自动填外键（`formula_template_id` / `herb_id`），从表**全量重建**（先删旧行再插新行）；任一失败整体回滚。
4. **API 约定**（§3.8）：前缀 `/api`；分页 `page`（默认 1）/`size`（默认 10）；统一响应 `{success,message,data,errorCode}`；业务异常一律 `raise ValueError("中文提示")`；写接口必须 `@login_required` + `@require_permission('<权限码>')`。
5. **字典**：M1 `data_dictionaries` 由注册表自动注册，前端经 `GET /api/meta/dictionaries` 取用；界面显示 label、存储 code。
6. **规则三层落地**（§3.6）：M1 `refRules`（属性级）→ service 保存时校验；M1 `invariants`（聚合级）→ service 保存时校验；M3 `rules`（跨对象）→ `utils/rules.py` 求值。**失败必须给中文提示**。
7. **前端**（§3.9）：复用 `styles/index.css` 与 `Modal`/`Pagination`/`toast`/`Badge`/`MenuIcon`；布局规则：单表一行 2 列、主从表主表一行 3 列 + 从表表格、查询条件一行 3 列 + 结果表格分页；品牌蓝 `#2266e3`、9pt 基准、标签右对齐。

| 方法 | 路径 | 权限码 | 入参 | 返回 |

### 4.4 饮片与库存 `/api/herb`

| 方法 | 路径 | 权限码 | 入参 |
|---|---|---|---|
| GET | `/api/herb` | `herb:save` | `page,size,herb_name,herb_category,herb_status`（建档维护用） |
| GET | `/api/herb/{id}` | `herb:save` | 主表 + `stock_flows[]`（近 N 行） |
| POST | `/api/herb` | `herb:save` | Herb 全字段（`herb_code`、`stock_quantity` 免填，后者由流水驱动） |
| PUT | `/api/herb/{id}` | `herb:save` | 同上（不改 `stock_quantity`） |
| POST | `/api/herb/{id}/status` | `herb:change-status` | `{herb_status}` |
| POST | `/api/herb/{id}/inbound` | `herb:inbound` | `{quantity, biz_date, inbound_no, remark}` → **事务内**写一条 `biz_type='INBOUND'`（`quantity` 为正）流水 + 同步 `stock_quantity += quantity`；**`quantity>0` 与 `inbound_no` 均为 M2 前置条件（必填）** |
| POST | `/api/herb/{id}/stocktake` | `herb:stocktake` | `{actual_quantity, biz_date, remark}` → 计算差异 `actual - stock_quantity`，生成 `biz_type='盘点调整'` 流水（`quantity=差异`）+ 同步 `stock_quantity=actual`；差异为 0 时提示「账实相符，无需调整」 |
| GET | `/api/herb/stock` | `herb:query-stock-and-alert` | `page,size,herb_name,herb_category,toxicity_level,alert_only,stock_from,stock_to` → 分页库存列表（含 预警标志 = `stock_quantity < low_stock_threshold`） |
| GET | `/api/herb/stock/export` | `herb:query-stock-and-alert` | 同查询条件，返回 CSV（UTF-8 BOM） |
| GET | `/api/herb/options` | 登录即可 | `keyword` → `[{id, herb_code, herb_name}]`（供方剂模板跳选框） |

- 对应 M7 对象 `QR-HERB-STOCK-001`（饮片库存与预警查询，`objectType=LIST_QUERY`）：查询参数与结果列以该对象定义为准（`herb_name/herb_category/toxicity_level/alert_only/stock_from/stock_to`；结果含编码、名称、类别、毒性分级、库存数量、预警值、预警标志、最近入库日期）。
- 校验：`min_common_dose > 0`、`max_common_dose >= min_common_dose`（REF-07）、`stock_quantity >= 0`、`low_stock_threshold >= 0`；**INV-03 库存对账**：`stock_quantity == SUM(herb_stock_flow.quantity)`（盘点/入库后必须成立，用 `RULE-HERB-STOCK-RECONCILE` 表达式 `stockQuantity - flowNetQuantity` 求差异）。
- `Herb_DeductStock` / `Herb_ReturnStock`（系统自动行为）本批**不实现**，批次 2 随调剂/作废联动落地。

## 5. 权限码与角色授权（由 `seed.py` 从 M5 自动生成）

**权限码派生规则**（对齐《指导书》§3.7 `{对象}:{动作}`；因 M5 的 `permissionId` 已表达对象与动作，故从 `targetRef` 行为 id 确定性派生）：

```
targetRef = {EntityAlias}_{ActionName}  →  权限码 = snake_case(EntityAlias) + ":" + kebab-case(ActionName)
例：Herb_QueryStockAndAlert → herb:query-stock-and-alert
    Patient_ChangeStatus    → patient:change-status
```

| M5 permissionId | 权限码 | 名称 | 授权角色 |
|---|---|---|---|
| `PERM-PATIENT-SAVE` | `patient:save` | 患者建档与修改 | ROLE-01 导诊员 |
| `PERM-PATIENT-STATUS` | `patient:change-status` | 患者停用与启用 | ROLE-01 导诊员 |
| `PERM-SYNDROME-SAVE` | `syndrome:save` | 证型字典新增与修改 | ROLE-05 科室管理员 |

## 8. 规则落地清单（本批必须真实生效）

| 规则 | 位置 | 落地方式 | 中文提示 |
|---|---|---|---|
| INV-01 证件联合唯一 | M1 Patient.invariants | service 保存前查重（`id_type`+`id_no`，排除自身、仅 `flag=1`） | 同一「证件类型 + 证件号码」不得重复建档 |
| REF-03 身份证格式 | M1 Patient | service 校验 18 位 + 校验位（`id_type='ID_CARD'` 时） | 证件类型为居民身份证时，证件号码须为 18 位且校验位正确 |
| 出生日期/年龄互斥必填 | M1 Patient | 至少一项 | 出生日期与年龄至少填写一项 |
| REF-07 常用量区间 | M1 Herb | `max >= min` | 常用最大量不得小于常用最小量 |
| 组成明细药味不重复 | M1 FormulaTemplate | 保存时查重 | 同一方剂模板内药味不得重复 |
| INV-03 库存对账 | M1 Herb | 入库/盘点后校验 `stock_quantity == SUM(flow.quantity)` | 库存数量必须等于该饮片全部出入库记录的数量净和 |
| R-06 饮片库存对账 | M3 `RULE-HERB-STOCK-RECONCILE` | `utils/rules.py` 求值 `stockQuantity - flowNetQuantity`，返回差异；`btnReconcile` 展示、盘点时以差异生成调整流水 | 库存与流水净和不一致，差异 X g |

> 未列出的 M3 规则（R-01 剂量、R-02 库存充足、R-03 毒性、R-04 作废分派、R-05 随访日期）属本批之外的行为，批次 2/3 落地；本批不得实现为「空壳」。
